2.Le fait qui structure tout M05

Le readiness check ne s'est pas contenté de constater l'absence de clés. Il a mesuré la connectivité réelle vers 14 endpoints, et interrogé l'état du proxy.

Preuve · proxy_status_evidence.json gateway answered 403 to CONNECT (policy denial or upstream failure)
pour api.elevenlabs.io · api.cartesia.ai · api.openai.com · api.deepgram.com · api.assemblyai.com · api.sync.so · api.hedra.com · fal.run · api.replicate.com · cloudflarestorage.com · francecentral.tts.speech.microsoft.com

Les hôtes Google répondent, eux, applicativement :
{"error":{"code":403,"message":"Method doesn't allow unregistered callers … Please use API Key","status":"PERMISSION_DENIED"}}

La distinction est décisive. Le DNS résout pour les 14 hôtes. Les fournisseurs bloqués sont coupés avant la poignée de main TLS ; Google répond une erreur d'API. Ce n'est donc pas un problème de credentials — c'est une politique réseau, et elle laisse passer exactement un fournisseur.

4.La dépendance la plus dangereuse

Le lip-syncCritique
Pourquoi
Elle est unique (aucune redondance joignable), bloquante pour H1 (sans elle, P0 ne peut pas conclure) et dominante économiquement — ~87 % du coût variable mesuré en M03.
Options
API tierce : bloquée par la politique réseau. Auto-hébergé (LatentSync, Wav2Lip) : aucun GPU dans cet environnement (/dev/nvidia* absent) et hôtes de poids injoignables. Équivalent Google : n'existe pas.
Levée
Autoriser l'hôte dans la politique du proxy, ou exécuter le harnais sur une machine à réseau ouvert.
Note
C'est le seul bloqueur du projet qui ne se résout pas avec de l'argent.
